7Employee Management

The Employees tab holds the office employee list. Unlike every other manager tab, this list is shared by every month — August, September and October all see and edit the same people. A name added in September is there in October.

7.1The employee list

ElementWhat it means
Token badgeThe employee's Token Number (TKN). This is their username. Tokens are unique across the office; the list is ordered by token, then by name.
Signed upThis token already has a login. The employee can sign in.
Not signed upThe token exists but nobody has claimed it yet. Tell the employee to visit /employee/signup.
No token number — can't sign up yetThe employee has no token, so there is nothing to sign in with. Give them one with Edit.
InactiveDeactivated: struck-through name, hidden from the public meal board, cannot sign up, and cannot change meals or see their bill if already signed up.

7.2Adding an employee

The form at the top of the tab: a Token box, a name box, and Add.

  • The name is required; the token is optional but an employee without one cannot sign in.
  • A token must be a whole number and must not already be in use — if it is, you get "Token N is already used by another employee." and nothing is saved.
  • New employees are active immediately and appear on the meal board straight away.

7.3Editing a name or token

Rule — a signed-up employee's token is frozen

The Token Number is the login. Once an employee has signed up, changing their token is refused: "This employee has already signed up with their token. Reset their login first, then change the token." Their name can still be corrected at any time.

7.4Reset login — the password recovery route

There is no "forgot password" e-mail anywhere in this application. Reset login is the entire recovery mechanism, and it is in the mess manager's hands.

  1. Press Reset login beside the employee.
  2. Confirm the warning, which names the employee and their token and states that their meals and deposits stay.
  3. The row goes back to Not signed up and a green message appears: "<Name> can now sign up again at /employee/signup."
  4. The employee signs up again with the same token and a new password.

Use it for a forgotten password, or when the wrong person claimed a token.

Reset login deletes only the login

It does not touch the employee record, their meal history, or their deposits. It is safe.

7.5Deactivate / Activate

Use this when somebody leaves, goes on long leave, or has not joined yet.

Deactivating an employee…Effect
Public meal boardThey disappear from it entirely.
Meal Status sheetThey stay, tagged Inactive, so history remains visible and correctable.
Their own panelSign-in still works, but the panel shows "Account deactivated — please contact the mess manager."
Sign-upBlocked.
ReportsThey still appear in any month where they ate or deposited, so their final bill is never lost.
Deposit dropdownThey are removed from the "Record a deposit" employee list.

Activate reverses all of it.

7.6Remove — and why it usually refuses

Remove deletes the employee outright. It is allowed only if the person has no meal history and no deposits in any month. Otherwise the application refuses:

"This employee has meal history and can't be deleted. Deactivate them instead."

This is deliberate, and the database enforces it independently of the application. Billing records must never silently disappear. For anyone who has ever eaten, Deactivate is the correct action — removal is only for a row typed in by mistake.

7.8Who can do all this

Any mess manager account — the current month's, a past month's, or a future month's. The employee list is office-wide and is not tied to a manager period. This is the one place where an outgoing manager can still change something that affects the current month, so treat it with care and agree changes with the month's team.
